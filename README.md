# website

The official website for Doubak! — 豆备的官方网站 · <https://doubak.com>

Plain static HTML and one stylesheet. **No build step, no dependencies.**
What is in this repo is exactly what is served — same principle as
[`doubak-extension`](https://github.com/Doubak/doubak-extension), for the same reason:
this project's whole thesis is auditability, and a site nobody can audit without
running a toolchain undercuts it.

Two GitHub Actions workflows do not change that: one checks link protocols, the other
regenerates `sitemap.xml`. Neither transforms a page — see [Automation](#automation).

Site content is in Chinese; the READMEs are the exception, per project convention.

## Layout

```
index.html            landing page
404.html              not-found page (GitHub Pages serves this automatically)
log/index.html        dev log index
log/YYYY-MM-DD-*.html dev log entries
log/_template.html    copy this to start a new entry
privacy/index.html    privacy policy
css/main.css          the entire stylesheet
assets/logos/         logo master set — SVG, PNG, .ico, and gen_logo.py
favicon.ico           copy of assets/logos/favicon.ico, for /favicon.ico requests
sitemap.xml           regenerated by CI on every push to main; do not hand-edit
tools/check-links.py  link-protocol check, also run by CI
.github/workflows/    link check + sitemap (see Automation)
CNAME                 doubak.com
.nojekyll             serve files as-is; do not run Jekyll
```

`assets/logos/` is the source of truth for the mark across the whole project —
`doubak-extension/icons/` holds byte copies of `icon-{16,32,48,128}.png`. Update
here first, then re-copy there. See `assets/logos/README.md` for which file goes
where, and regenerate with `rsvg-convert`, never cairosvg.

Which SVG this site uses where — the display master only in the one big spot,
everything small gets a small-size tier:

| Where | File |
|---|---|
| Hero lockup on `index.html`, 64px | `doubak-icon.svg` (display master, has 豆) |
| Header brand mark, every page, 24px | `doubak-icon-mid.svg` |
| `<link rel="icon">` SVG favicon, every page | `doubak-icon-small.svg` |
| `/favicon.ico` fallback | `favicon.ico` (16+32+48) |
| `apple-touch-icon`, `og:image` | `icon-180.png`, `icon-512.png` — already display-tier |

Changing any of these means touching all 27 HTML files, since each carries its
own `<head>`. Sweep with grep, not by hand.

## Local preview

Any static file server works. Pages use absolute URLs (`/css/main.css`), so serve them
rather than opening `file://`:

```sh
python3 -m http.server 8000    # then http://localhost:8000
```

## Adding a dev log entry

1. Copy `log/_template.html` to `log/YYYY-MM-DD-slug.html` and fill in the `{{...}}` placeholders.
2. Add an entry at the top of the list in `log/index.html`.
3. Add it to the "最近的开发日志" section on `index.html`, keeping only the newest three.
4. Point the previous entry's `.post-nav` at the new one.

There is no generator, so steps 2–4 are manual by design — the trade for having no
toolchain. The cost is per entry added, not per entry that exists — steps 2–4 touch
four files no matter how long the log gets. At 22 entries it is still about a minute.

## Deploying

GitHub Pages serves `main` from the repository root.

- **Settings → Pages → Source:** Deploy from a branch, `main` / `/ (root)`.
- **Custom domain:** `doubak.com` — the `CNAME` file in this repo is what sets it.
  Enable "Enforce HTTPS" once the certificate is issued.
- **DNS**, at the registrar for `doubak.com`:

  | Type | Name | Value |
  |---|---|---|
  | A | `@` | `185.199.108.153` |
  | A | `@` | `185.199.109.153` |
  | A | `@` | `185.199.110.153` |
  | A | `@` | `185.199.111.153` |
  | CNAME | `www` | `doubak.github.io` |

  (Or a single `ALIAS`/`ANAME` on the apex pointing at `doubak.github.io`, if the
  registrar supports it. Verify against the
  [current GitHub Pages addresses](https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)
  before relying on the table above.)

## Automation

Two workflows, neither of which builds or rewrites a page.

**`check.yml` — link protocols.** Runs on every push and pull request. An `http://`
link on an https page gets blocked or downgraded as mixed content while looking
exactly like a working link, so `tools/check-links.py` flags them. Run it locally the
same way CI does:

```sh
python3 tools/check-links.py .
```

**`sitemap.yml` — sitemap.** Runs on every push to `main` (and on demand from the
Actions tab), regenerates `sitemap.xml` with
[`cicirello/generate-sitemap`](https://github.com/cicirello/generate-sitemap), and
commits it straight back to `main` as `github-actions[bot]`. A generated file with
nothing to review does not need a pull request in the loop — but it does mean
**`git pull` before your next push**, or you will be working off a stale `main`.

Worth knowing:

- `404.html` and `log/_template.html` are kept out, via `exclude-paths` in the workflow.
- `index.html` becomes a directory URL: `log/index.html` → `https://doubak.com/log/`.
- Each `<lastmod>` is that file's last commit date, which is why the checkout asks for
  the full history (`fetch-depth: 0`).
- A page carrying `<meta name="robots" content="noindex">` is dropped automatically.
  That is the way to keep one more page out without touching the workflow.
- The bot's own push does not re-trigger anything — pushes made with `GITHUB_TOKEN`
  never trigger workflows — so there is no loop.

The sample-site repo runs the same action behind a pull request and a post-processing
script, because it has ~700 paginator redirect stubs and ~600 non-ASCII tag URLs to
clean up. This site has neither, so it needs neither.

## Ground rules

- No analytics, no third-party requests, no cookies, no web fonts. Keep it that way;
  the footer promises it on every page.
