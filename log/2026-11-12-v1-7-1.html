v1.7.1：导出失败后，清理中转并保留原始档案

修复 ZIP 空间不足时继续写入和半成品提交，增加中转占用与清理入口，修复失效目录句柄。档案格式与权限不变，GitHub Release 提供两个浏览器包。

v1.7.1 已发布到 GitHub Release。 这是针对 #35 的修复版本， 同时覆盖“档案”的原始导出，以及“导出”的结构化数据、NeoDB 和 Markdown。

失败及时停止，临时文件可以清理

ZIP 任一成员写入失败便停止整包，放弃未完成写入并尝试清理；不下载半成品，也不记录为已导出。 清理失败明确提示，保留最初的错误。已交给下载的成品不会因后续界面错误而被删除。 Chrome、Edge 的原子目录写入失败也会保留原有目标文件。

“档案”页新增 ZIP 中转占用、浏览器配额估算和清理按钮。清理前需确认旧下载完成或取消， 不能删除另一个面板正在打包的文件。原始档案 ZIP 会按实际大小预检配额， 但配额不能保证物理磁盘空间；Firefox 仍需要中转 ZIP 和下载文件各一份空间。

发布前的 Firefox 实测还发现：打包结束后立即重试或清理，可能误报“另一个面板正在打包”。 现在会等待浏览器真正释放打包锁，回归测试覆盖完成、取消、写入失败和手动清理四条路径。

另修复目录删除／重建后继续使用失效句柄的读取问题。只读扫描不创建缺失目录， 瞬时的目录不存在会重列一次；持续错误仍报告，不隐藏档案。 具体处理方法见ZIP 空间不足指引， 决策与验证细节见修复记录。

兼容性与发布范围

档案格式继续使用 bundle/1.5，不迁移或改写原始档案；ZIP 内部布局、账号隔离和导出命名规则不变。 没有增加权限，Firefox 最低版本仍为 142。广播首屏的采集范围不变。

GitHub Release 提供 Chrome／Edge 与 Firefox 两个 ZIP。应用商店需分别提交审核， 不会随 GitHub Release 自动更新；安装后请核对版本号。 Firefox 155 的真实 OPFS 测试已验证失败清理、立即重试和源文件不变； 故障注入、回归测试与打包检查不代替原先磁盘用尽环境的实际复测。
