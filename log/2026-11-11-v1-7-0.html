v1.7.0：广播回复首屏，以及两类抓取恢复修复

本人广播可以选择保存回复首屏原始快照；修复切换登录后的新任务误拦、权限拒绝导致整场暂停，以及短评历史展示。新档案采用 bundle/1.5，保留旧档案读取能力。

v1.7.0 已在 GitHub Release 发布， 提供 Chrome／Edge 和 Firefox 两个安装包。应用商店需分别上传审核，商店版本不会随 GitHub Release 自动更新。 Firefox 包要求 142 及以上版本。

广播多保存一页对话证据

“保存广播回复首屏”默认关闭，仅限当前登录者自己的账号，重开面板后需重新勾选。 开启后，有回复的本人 status 与已支持的 personal topic 会分别保存详情 HTML 和一个回复 API 首屏。 增量补未成功项，刷新模式重抓已知首屏和可编辑 topic 详情，全量重新保存本轮发现的合格项。

不翻页、不展开楼中楼、不另抓回复者主页与附件。这些快照只留在原始档案， 不进入个人 Canonical、网站、搜索或平台导出；首屏成功也不代表完整讨论。 具体操作见使用说明， 实测过程见广播回复开发记录。

新任务和继续旧任务，各自核对身份

修复终止旧任务、切换登录后，新任务仍被旧操作者误拦的问题。 面板重新核对范围期间，旧的开始按钮不能提交；继续旧任务仍要求原目标和操作者， 不允许换个账号接着写同一份档案。详见身份与面板修复记录。

单篇无权访问，留下缺口让其他内容继续

对已核验的电影影评权限错误模板，记录独立失败与缺口，其他内容继续抓取。 显式重试成功后修复缺口，崩溃恢复也以已提交的响应为准。一般风控、验证码、限流仍暂停整场任务。 调查与测试见权限拒绝修复记录。

新档案格式为 bundle/1.5，新增 denied 判定。 更新后的工具继续读取旧档案；旧校验器可能拒绝新判定，处理新档案时应同步更新解析器、规范和导入适配器。

历史展示与验证边界

本版同时更新内置站点生成器，保留短评的中间版本，以日期和版本编号区分同日修改； 只在证据一致时合并展示广播与原页短评来源。 历史展示记录说明了这次修复的依据。

广播快照已有 Chrome 实际导出、离线重算和自动化恢复验证。 Firefox 登录态回复抓取，以及两种浏览器完整的跨轮、刷新和暂停重载人工矩阵仍待验收。 发布包含这些已知验证边界，没有把打包通过写成所有实机情形都验证过。 完整变更与兼容说明见发布说明。
